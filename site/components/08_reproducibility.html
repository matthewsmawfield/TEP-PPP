Data Availability & Reproducibility

This work follows open-science practices. All results are fully reproducible from raw data using the documented pipeline. All numerical results, kernel predictions, and statistics are generated by deterministic Python scripts processing real GNSS observational data.

Repository and Code

GitHub Repository: github.com/matthewsmawfield/TEP-PPP

The repository contains a deterministic, version-controlled analysis pipeline. The numbered scripts (step_01..step_181) record a complete chronological log of every analysis run — pre-registered evaluations, primary analyses, adversarial null controls, and exploratory checks alike — so that readers can enumerate the full set of tests rather than a selected subset, organised into five evidentiary pillars: (i) data acquisition, preprocessing, and common-mode control batteries on broadcast and precise products (Steps 01–03c, 06, 10–19, 32, 38, 40, 45–45b); (ii) physical field characterisation and geometry-free channels, including cross-spectral phase alignment, cross-constellation satellite-clock pairs, sub-diurnal CMB-axis aperture synthesis, oscillator-class screening, co-located monument differentials, and the 65-day European optical-fibre clock network reanalysis (Steps 27, 50, 53, 58–59, 65–65d, 75–80, 98, 103, 137, 158–167, 178–179, 181); (iii) causal clock outage bridging and timing holdover across EUREF and multi-year global archives (Steps 25, 34, 55–56, 60, 85–90, 96, 104b, 140, 153); (iv) degraded-geometry positioning and blind localisation across raw-observation code SPP, production PRIDE-PPP-AR, and carrier-phase outage solves (Steps 22–23, 26, 33/39, 44, 48, 52, 57, 62, 99, 106); and (v) the live 68-station NTRIP observatory, cryptographically sealed ex-ante evaluation, and clean-origin prospective preregistration suite (Steps 37–37c, 168–174, 180). The Kalman-filter simulations (Steps 04, 07, 20) are exploratory and not relied on for any claim. All steps are orchestrated by scripts/run_pipeline.py with per-step logging.

All raw RINEX data, PPP processing configurations (RTKLIB), the TEP spatial kernel implementation, and analysis scripts are released openly in the project repository under CC-BY 4.0 (DOI: 10.5281/zenodo.23704945). Reproduction Instructions

Quick Start (Full Reproduction)

# 1. Clone repository
git clone https://github.com/matthewsmawfield/TEP-PPP.git
cd TEP-PPP

# 2. Install dependencies
pip install -r requirements-lock.txt

# 3. Run the curated evidence pipeline (downloads data when absent)
python scripts/run_pipeline.py

# 4. Non-destructive code/result/manuscript verification
python scripts/reproduce.py --verify-only

# Results are stored in results/outputs and the gate ledger in EVIDENCE_STATUS.md

Sealed-Envelope Ex-Ante Verification (Step 174)

The cryptographic sealed-envelope protocol is independently auditable. The replay suite re-derives every seal origin from the archived Gram matrices and reruns the full falsification battery: 

# Replay all 24 sealed-envelope origins + falsification battery
# (~60-90 min; re-derives every seal's eigendecomposition and the full
#  lambda x lead x epoch-position lattice from the archived Grams)
python scripts/steps/step_174_sealed_envelope_prediction.py

# Verify a live sealed envelope: SHA-256 integrity, then score every
# post-seal window against the committed frozen weights
python scripts/live/sealed_envelope_verifier.py --verify

# Retrospective N-window walk-forward backtest under the sealed protocol
python scripts/live/sealed_envelope_verifier.py --backtest 8

# Live watch mode: score each new post-seal window as it is solved;
# --seal-every mints a fresh envelope per window and --anchor appends
# each seal's digest to the hash-chained anchors.log provenance record
python scripts/live/sealed_envelope_verifier.py --watch 60 --seal-every --anchor

# Verify every envelope against all post-seal windows (lead-decay ladder)
python scripts/live/sealed_envelope_verifier.py --verify-all

# Verify the 122-link hash-chained anchor log and full 7,262-pair lattice audit
python scripts/live/anchor_chain_status.py
python scripts/live/sealed_lattice_audit.py

# Re-run the satellite-scale reconciliation (Step 178), CMB-axis cluster
# robustness (Step 179), clean-origin prospective preregistration (Step 180),
# and 65-day European optical-fibre clock network reanalysis (Step 181)
python scripts/steps/step_178_satellite_scale_reconciliation.py
python scripts/steps/step_179_axis_robustness.py
python scripts/steps/step_180_prospective_preregistration.py
python scripts/steps/step_181_european_optical_fiber_2023.py

Each sealed envelope in data/ppp_live/sealed_envelopes/ stores the seal timestamp, the cutoff window identity, the member Gram list, the frozen weight archive, and its SHA-256 digest; verification_log.json appends every scored post-seal window with the recomputed digest, so any alteration of the committed weights invalidates the chain. The append-only anchors.log hash-chains every seal's digest to its predecessor (anchor_sha256 = SHA-256(prev ‖ weights ‖ utc)), producing an externally publishable timestamped provenance record. Because archived Grams are built on each member window's own holdout, the reported one-step skill is additionally bounded by the resubstitution, strict-future epoch-slice, 3,600/7,200 s embargo, and zero-overlap clean-origin controls tabulated in Section 3.9.
